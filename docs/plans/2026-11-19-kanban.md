# GPUI Kanban Board Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** A small macOS kanban board (To Do / Doing / Done) built with the official `gpui` 0.2.2 crate: drag & drop, add/delete cards, auto-saved to JSON.

**Architecture:** `src/board.rs` is a pure, unit-tested data model (cards with a status, load/save as JSON). `src/main.rs` is one GPUI view entity (`KanbanBoard`) that owns the `Board`, renders three drop-target columns of draggable cards, and has a minimal hand-rolled text field per column. Every mutation saves then calls `cx.notify()`.

**Tech Stack:** Rust 2024 edition, `gpui` 0.2.2, `serde`/`serde_json`, `dirs` (Application Support path), `tempfile` (tests only).

Design: `docs/plans/2026-11-19-kanban-design.md`.

Verified against gpui 0.2.2 source:
- `on_drag(value, |value, offset, window, cx| -> Entity<W: Render>)` needs a stateful element (`.id(..)`).
- `on_drop::<T>(listener)` / `drag_over::<T>(|style, &T, window, cx| style)` work on plain `div()`.
- `track_focus(&handle)` auto-focuses the element on mouse down.
- `KeyDownEvent.keystroke.{key, key_char, modifiers.{platform, control}}`; keys are `"enter"`, `"backspace"`, `"escape"`, `"space"` (with `key_char = " "`).
- Key bindings (cmd-q) are matched *before* `on_key_down` listeners run.

No git repo exists; commit steps are skipped unless the user runs `git init`.

**Step 2:** Run `cargo test`. Expected: all 9 FAIL (panicked at `not yet implemented`).

**Step 3: Implement** `Status::{ALL, label}`, `Board::{sample, add, delete, move_to, cards_in, load, save}`, `default_path()`:
- `move_to`: no-op if unknown id or same status; otherwise remove, set status, push to end.
- `save`: `create_dir_all(parent)`, write `board.json.tmp`, rename over `board.json` (atomic).
- `load`: NotFound → sample; read error → log + sample; parse error → rename to `.json.bak`, log, sample; success → `next_id = max(next_id, max_id + 1)`.

### Task 3: Kanban UI
